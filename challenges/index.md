## The mandatory MLH challenge

Every Hacktoberfest Hack Day automatically runs the **[Best Open-Source AI Project](https://hacktoberfest-handbook.mlh.com/fest-planning-guide/open-source-prize-categories)** challenge. It has one winning team, decided through MLH OrganizerHQ, and every member of the winning team gets a DEV Badge (plus MLH+DEV swag, where available).

To qualify for it, your project must:

- Use **open-source or open-weight AI as an important part of how it works**
- Live in a **public GitHub repository under an open-source license**
- Fall into (at least) one of: **built with an open-weight LLM/SLM**, **an Agent Skill**, or **a model harness** (original or a meaningful extension of an existing one)

All 5 challenges below are built to clear this bar — pick whichever matches your team's interests, then submit to **both** that challenge and Best Open-Source AI Project on OrganizerHQ (see [Rules → Submitting your project]({{ site.baseurl }}/rules/#submitting-your-project)).

## The 5 challenge tracks

| # | Challenge | MLH category it maps to | Best for a team that likes... |
|---|---|---|---|
| 1 | [Build a Gemma Agent Skill]({{ site.baseurl }}/challenges/01-agent-skill/) | Agent skill | Packaging expertise for AI coding agents |
| 2 | [Gemma Off the Grid]({{ site.baseurl }}/challenges/02-edge-offline/) | Open-weight SLM | Systems, performance, offline-first thinking |
| 3 | [Multimodal Campus Companion]({{ site.baseurl }}/challenges/03-multimodal-assistant/) | Open-weight LLM | Product design, accessibility, user-facing apps |
| 4 | [Gemma-Powered Dev Harness]({{ site.baseurl }}/challenges/04-dev-harness/) | Model harness | Developer tooling, CLIs, agent architecture |
| 5 | [Campus Knowledge Companion (RAG)]({{ site.baseurl }}/challenges/05-rag-knowledge-companion/) | Open-weight LLM + retrieval | Data, search, grounding AI in real sources |

You may enter **more than one** challenge with the same project if it genuinely qualifies for both — just select every eligible challenge when you submit.

## How these are judged

Every challenge shares one base rubric (problem & impact, use of Gemma, technical execution, originality, open-source quality), plus a short list of challenge-specific bonus criteria noted on each challenge's page. Full detail: [Judging]({{ site.baseurl }}/judging/).

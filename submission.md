# Submit Your Project

Start with the [idea canvas]({{ site.baseurl }}/templates/problem-statement/), publish a useful [README]({{ site.baseurl }}/templates/project-readme-template/) and rehearse the [demo flow]({{ site.baseurl }}/templates/demo-script/). These are reusable aids, **not replacements for the official submission form**. There is no mandatory application type or fixed project track.

## Where to submit

Use this event's [OrganizerHQ Challenges page](https://www.mlh.com/events/hacktoberfest-hack-day-nairobi-x-itech-club/challenges). **One submission can enter every category it qualifies for**, as both live prize pages state:

- [Best Open-Source AI Project](https://www.mlh.com/events/hacktoberfest-hack-day-nairobi-x-itech-club/challenges/01a0d987-0c41-12ea-13ac-5b85755dc2f3)
- [Best Use of Gemma 4](https://www.mlh.com/events/hacktoberfest-hack-day-nairobi-x-itech-club/challenges/01a03b87-be22-9180-5e2d-b3beeb66666d)

Do not create duplicate projects or repositories to enter both. Selecting categories does not establish eligibility, and permission to enter both is not a confirmed policy allowing the same team to win both. DigitalOcean is optional.

## Handbook-documented submission workflow

1. Register through OrganizerHQ and check in as instructed. One team member submits on behalf of the team, signed in with the account used to register.
2. Open the event's Challenges area. The handbook says **Add Submission** is available during the saved submission window; follow the current event interface rather than assuming a missing control means submission succeeded.
3. Supply the project link, project name, description and technologies used. For the open-source award, the project link must be a **public GitHub repository** with a clear code licence. Add a demo URL if available.
4. Under the form's category selection, choose every category the project is eligible to enter. The handbook calls this **Which challenge(s) are you submitting to?**; use the actual live form and confirm any differences with staff.
5. Submit before the confirmed close. The handbook calls the final control **Submit Project**. Check the saved entry's repository URL, project details and entered categories; do not treat a README, canvas or unsent form as a completed submission.

The handbook documents no separate licence-attestation field: make the licence clear in the repository. No extra canvas upload, duplicate repository, invented mandatory demo field or new category-selection step is imposed here. Complete any additional fields actually required by the live form after staff verify them.

## What to have ready

- Public repository, project name, concise description and actual technologies.
- Useful README with exact model/variant, inference route, model terms, dependencies, setup, tests, limitations and team contributions.
- Appropriate project-code licence, permitted data and honest original-work disclosure.
- Working demo and optional accessible demo/video URL, using no private data or exposed secrets.
- Evidence for each entered category; confirm [category-specific conditions]({{ site.baseurl }}/challenges/#the-official-mlh-challenge) rather than assuming a keyword or provider account is enough.

Use the complete [pre-submission checklist]({{ site.baseurl }}/templates/submission-checklist/) before submitting. Keep the repository public and your working demo ready for human judging. Staff should reconcile unique projects and category entries in OrganizerHQ; multiple category entries do not mean teams must submit duplicate project forms.

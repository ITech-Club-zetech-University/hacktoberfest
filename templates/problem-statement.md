# Problem Statement Worksheet

Copy this into your team notes or README and answer briefly. Use the [seven-step idea framework]({{ site.baseurl }}/challenges/#develop-an-idea-quickly) to refine it. This is a planning aid, not an additional submission form or idea-approval gate.

```text
Project name:
Problem:
Primary user:
Why the problem matters:
Current alternative or workaround:
Proposed solution:
What the AI model will do:
Why an open model is appropriate:
Why Gemma 4 is being used (if applicable):
Data and tools required:
Main risks or limitations:
MVP features for the hack period:
How the team will demonstrate success:
```

## Concise solution statement

“For [specific user] who needs [specific outcome], we are building [solution]. The AI component will [specific role], helping the user to [measurable or observable benefit].”

## Quick feasibility check

- Can you explain one user journey without saying “a platform for everyone”?
- Would a simpler non-AI approach work better? What specifically needs an open model?
- Can you access permitted test data and run the selected model on your actual hardware or API account?
- What will remain under human control?
- Can you demonstrate the core flow, one edge case and one failure/uncertainty case?
- Does the scope fit the [organiser-confirmed time available]({{ site.baseurl }}/rules/#the-hacking-timeline), with time left for testing, documentation, submission and rehearsal?

Cut features until the answers are credible. State an observable success check; do not invent user validation or claim tests you have not run.
